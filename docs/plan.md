# KYC-NLI project plan

Status: **Phase 0 complete** (2026-09-06). The pilot ran and returned a result
that changes the framing of the whole project. Read "The Phase-0 finding" before
planning anything else.

---

## The Phase-0 finding

The review prompts in `PROMPTS.md` anticipated the central objection:

> Cross-field temporal/numerical consistency is expressible as deterministic
> rules over a small closed field schema. If a rule baseline gets 99% on this,
> the NLI contribution collapses.

So the first thing built was that rule baseline — a transliteration-aware rule
engine with the ICAO Doc 9303 tables, MRZ check digits, date-format
normalisation, cross-field temporal rules and tuned fuzzy thresholds. Then the
same synthetic benchmark was generated at four OCR-noise levels and both
baselines were run on it.

| OCR noise | exact match macro-F1 | **rule engine macro-F1** | rule contrast consistency | rule false-mismatch |
| --- | --- | --- | --- | --- |
| clean | 0.371 | **0.980** | 0.952 | 0.000 |
| light | 0.359 | **0.903** | 0.793 | 0.098 |
| moderate | 0.353 | **0.831** | 0.652 | 0.133 |
| heavy | 0.285 | **0.649** | 0.396 | 0.156 |

Read the first row. **On noise-free input the deterministic rule engine reaches
0.980 macro-F1 and 0.952 contrast-group consistency.** There is roughly two
points of headroom. A neural document-level NLI model cannot produce a
publishable result on clean cross-script field matching, because the problem is
already solved by a lookup table and a fuzzy-match threshold.

The rule engine degrades steeply as OCR noise rises, and it degrades in a
specific, diagnosable way: corrupted strings stop parsing, the engine loses the
evidence it needs, and it abstains. Human review load goes from 29% to 56%
between clean and heavy noise.

**Therefore the contribution lives in the noisy regime, not the clean one.** The
defensible claim is not "NLI beats string matching at identity verification" —
a rule engine already does that. It is:

> Under realistic OCR corruption, a learned document-level entailment model
> recovers decisions that a transliteration-aware rule engine must abstain on,
> reducing human review load at equal or better error rate.

That is a claim about **selective prediction under input corruption**, it has a
strong baseline that is genuinely hard to beat, and it is falsifiable by the
risk–coverage curve.

### Caveat, stated plainly

The noise model is hand-built from documented per-script OCR failure modes, not
calibrated against a real OCR engine. The *direction* of the finding is robust —
it follows from the rule engine's brittleness to unparsable strings — but the
*magnitude* of the degradation is not yet trustworthy. Calibrating the noise
model against a real engine on MIDV-2020 crops is now the highest-priority
task, because every headline number depends on it. Tracked as
`docs/decisions/0004-ocr-noise-is-simulated.md`.

## Feasibility gates

| Gate | Status | Assessment |
| --- | --- | --- |
| **Data** | 🟡 AMBER | Real identity documents are legally uncollectable. The repo generates fully synthetic instances from embedded name pools, which is legally releasable but attackable as "an artifact of the generator". The mitigation is MIDV-2020 (mock identities on real document templates, free for research) as the realism anchor. Redistribution terms for derived annotations must be confirmed before any release. |
| **Labels** | 🟢 GREEN | Gold labels are generated by construction, not annotated, so they are free and perfectly consistent. A human-labelled subset (~500 instances) is still needed to show the definitions are usable by people; budget one week. |
| **Compute** | 🔴 RED locally, 🟢 GREEN on free tiers | Dev machine is 8 GB RAM, Intel Iris Xe, **no CUDA**. Nothing neural trains here. All of Phase 0 runs on CPU in seconds; Phase 1 fine-tuning must happen on Colab/Kaggle free GPU. This caps the model at roughly XLM-R base / mDeBERTa-v3 base — which is fine, and should be stated as a deliberate constraint rather than hidden. |
| **Scope** | 🟡 AMBER | OCR and transliteration both have mature off-the-shelf options and neither is a contribution. Transliteration is already off-the-shelf here (ICAO tables). Real OCR should stay off-the-shelf (Tesseract/EasyOCR) and be used only to calibrate the noise model. |
| **Evaluation** | 🟢 GREEN | The rule engine exists, is strong, and is in the repo. Nobody can accuse this project of a strawman baseline. |
| **Ethics / legal** | 🟢 GREEN | No real PII at any point; `Provenance.contains_real_pii` is asserted false by the test suite. `.gitignore` blocks image formats repo-wide. No IRB needed while the data stays synthetic; that changes the moment a real document is touched. |

## Critical path

```
[done] Phase 0  schema + generator + rule baseline + eval harness
   |
   v
Phase 0.5  calibrate the noise model against a real OCR engine   <-- SINGLE POINT OF FAILURE
   |
   v
Phase 1  fine-tune XLM-R / mDeBERTa on Colab; beat the rule engine at moderate+ noise
   |
   +--> Phase 2a  selective-prediction analysis (risk-coverage, review-load reduction)
   +--> Phase 2b  human-labelled validation subset
   |
   v
Phase 3  ablations, error analysis, write-up
```

**The single task whose slippage sinks the timeline is noise-model
calibration.** Every number in the paper is conditional on the noise model being
a fair proxy for real OCR. If it is not, the headline result is an artifact and
a reviewer will say so.

The go/no-go signal on the revised central claim is available at the end of
Phase 1: if a fine-tuned model does not beat 0.831 macro-F1 at moderate noise
*and* improve the risk–coverage curve, the claim is false.

## Risk register

| Risk | Likelihood | Impact | Early warning | Mitigation | Fallback contribution |
| --- | --- | --- | --- | --- | --- |
| Noise model is not a fair proxy for real OCR | High | Fatal to headline | Measured CER on MIDV crops differs from the simulated rate by >2x | M1 calibration before any model training | Report the calibration itself: a per-script OCR error characterisation for identity documents is publishable on its own |
| Neural model fails to beat the rule engine even under noise | Medium | Fatal to central claim | Dev macro-F1 below 0.83 after one training run | Hybrid: model only adjudicates instances the rule engine abstains on | Negative result plus the benchmark and the strong baseline — genuinely useful, and honest |
| Synthetic benchmark dismissed as generator artifact | High | Major | Reviewer says "your model learned your noise model" | M2 real name data; M5 human validation; report cross-generator transfer | Position the benchmark as a diagnostic contrast set rather than a leaderboard |
| No GPU access when needed | Medium | Schedule | Colab quota exhausted mid-run | Kaggle (30 GPU-hr/week) as second source; checkpoint every epoch | Smaller model; the claim does not depend on scale |
| MIDV / Dakshina licensing blocks release | Medium | Moderate | Terms review at M1/M2 | Release annotations + generation code, not derived images | Code-and-protocol release, which is standard for this data situation |

## What this plan deliberately does not do

- **No OCR research.** OCR stays off-the-shelf. Building an OCR model would cost
  weeks and contribute no novelty.
- **No transliteration research.** ICAO tables are normative and already in the
  repo. The interesting Hindi case is handled as a variant set, not a model.
- **No forgery / vision detection.** Half the literature review is vision-based
  ID forgery detection. It is adjacent, not this project. Cite it, distinguish
  it, do not build it.
- **No LLM prompting pipeline.** A zero-shot LLM baseline is worth *one table
  row* as a reference point. It is not the method.
